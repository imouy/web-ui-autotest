# UI自动化测试框架骨架生成执行模板

## 1. 文档定位

本文档是 `UI自动化测试框架骨架生成指示集规范.md` 的执行配套文档。

如果说规范文档负责定义“必须遵守什么”，那么本文档负责定义：

- 如何调用 AI 执行该规范
- 在执行前需要补齐哪些输入
- 在执行后 AI 需要按什么格式回报结果

本文档不负责定义框架结构本身，也不替代规范文档。

---

## 2. 使用方式

当你准备在一个空项目中生成 UI 自动化测试框架骨架时，应按以下顺序使用文档：

1. 先让 AI 阅读 `UI自动化测试框架骨架生成指示集规范.md`
2. 再向 AI 提供本文档中的输入模板
3. 要求 AI 按规范文档和本文档一起执行
4. 生成完成后，要求 AI 按本文档中的输出回执模板回报结果

你不得只给 AI 一个口头目标，而不提供必要输入。

---

## 3. AI 调用提示模板

以下内容可作为调用 AI 的标准入口提示。

### 3.1 标准调用版

```md
请先阅读当前项目中的《UI自动化测试框架骨架生成指示集规范.md》。

你的任务不是生成完整业务测试，而是基于该规范生成一套 UI 自动化测试框架骨架。

请严格按规范中的固定技术栈、固定结构、职责边界、禁止项和合格标准执行。

我会继续提供本次生成任务的输入项。

在输入不足时，请优先生成通用骨架，不要擅自伪造业务页面细节。

生成完成后，请按“输出回执模板”说明：
1. 你生成了哪些目录和关键文件
2. 哪些文件属于示例
3. 哪些地方因为输入不足采用了通用实现
4. 哪些地方需要我后续补充
```

### 3.2 强约束调用版

适用于你希望 AI 尽量少自由发挥的场景。

```md
请先完整阅读《UI自动化测试框架骨架生成指示集规范.md》，并严格按其中规则执行。

本次任务只允许生成 UI 自动化测试框架骨架，不允许擅自扩展为：
- 完整业务测试用例
- 真实定位器补全
- 复杂断言策略
- 回归集设计

请固定使用：
- Python
- Playwright for Python
- Pytest
- POM
- Allure

并且必须保证：
- 执行测试后自动生成 Allure HTML 报告
- 执行测试后自动打开 Allure HTML 报告首页
- 测试失败截图同时挂载到 Allure 用例附件

请严格按输入项生成目录结构、关键文件和最小可运行骨架。

如果输入不足，请明确指出缺失项，并先生成通用骨架，不得编造业务细节。

生成完成后，必须按输出回执模板汇报结果。
```

## 4. 输入填写模板

以下模板用于在生成框架前向 AI 提供输入。

### 4.1 最小输入模板

```md
项目名称：
被测系统名称：
基础 URL：
浏览器类型：
是否无头运行：
浏览器通道：
是否启用截图：
是否启用 trace：
是否启用 video：
报告目录名称：
证据目录名称：
Python 包路径或模块根目录约定：
页面模块清单：
页面对象命名方式：
```

### 4.2 推荐填写说明

- 项目名称：本次测试工程名称
- 被测系统名称：业务系统名称
- 基础 URL：系统首页或登录页地址
- 浏览器类型：如 `chromium`、`firefox`、`webkit`
- 是否无头运行：如 `true/false`
- 是否启用截图：如 `true/false`
- 浏览器通道：如 `msedge`、`chrome`；如无要求可写 `无`
- 是否启用 trace：如 `true/false`
- 是否启用 video：如 `true/false`
- 报告目录名称：如 `reports`
- 证据目录名称：如 `artifacts`
- Python 包路径或模块根目录约定：如无需包结构可写 `无特殊要求`
- 页面模块清单：如 `登录页、首页、订单页`
- 页面对象命名方式：如 `LoginPage / HomePage / OrderPage`

默认执行要求，无需额外输入也应实现：

- 测试执行后自动生成 Allure HTML 报告
- 测试执行后自动打开 Allure HTML 报告首页
- 失败截图自动作为 Allure 附件挂载

### 4.3 示例输入

```md
项目名称：demo_ui_test
被测系统名称：CRM后台系统
基础 URL：https://demo.example.com/login
浏览器类型：chromium
是否无头运行：true
是否启用截图：true
是否启用 trace：true
是否启用 video：false
报告目录名称：reports
证据目录名称：artifacts
Python 包路径或模块根目录约定：无特殊要求
页面模块清单：登录页、首页
页面对象命名方式：LoginPage、HomePage
```

## 5. 输入不足时的处理规则

当输入不完整时，AI 应按以下规则处理：

1. 缺少基础 URL 时，可保留占位配置，但不得伪造真实地址
2. 缺少页面模块清单时，应只生成通用示例页面对象
3. 缺少命名方式时，应采用清晰、常规、可维护的默认命名
4. 缺少运行选项时，应使用保守默认值，并在回执中说明

核心原则：

**宁可生成通用骨架，也不要伪造业务细节。**

AI 在生成完成后，应按以下格式回报结果。

### 6.1 标准回执模板

```md

### 1. 已生成的目录
- 

### 2. 已生成的关键文件
- 

### 3. 示例文件
- 

### 4. 通用实现说明
- 哪些地方因输入不足采用了通用实现

### 5. 需要补充的信息
- 

### 6. 自检结果
- 结构是否完整：
- 技术栈是否一致：
- 页面层与测试层是否分离：
- 是否支持报告输出：
- 是否支持失败证据输出：
- 是否已生成 Allure HTML 报告：
- 是否已自动打开 Allure HTML 报告：
- 失败截图是否已挂载到 Allure 用例附件：
```

### 6.2 回执要求

AI 在回执中必须说清：

- 生成了什么
- 没生成什么
- 为什么没生成
- 哪些是占位
- 哪些地方需要后续补充
- Allure HTML 报告是否真实生成
- 测试完成后是否真实自动打开了 HTML 报告
- 失败截图是否既落到了证据目录又挂到了 Allure 附件

你不得只接受“已完成”这种没有细节的回复。

---

## 7. 输出验收要点

在你接收 AI 生成结果时，应重点检查：

1. 是否真的生成了完整目录，而不是只给了目录示意图
2. 是否真的生成了关键基础文件
3. 是否页面层和测试层职责清晰
4. 是否出现了大量业务细节编造
5. 是否使用了错误技术栈
6. 是否给出了清晰回执
7. 是否真的生成了 Allure HTML 报告，而不是只创建目录
8. 是否在测试完成后自动打开了 HTML 报告
9. 是否把失败截图挂到了 Allure 用例附件中

如果以上关键点不成立，本次执行不能视为合格。

---

## 8. 与规范文档的关系

你必须始终理解：

- 规范文档负责定义规则
- 本文档负责定义调用与执行格式

两者缺一不可。

如果只有规范文档，没有本文档，AI 往往不知道如何被调用。

如果只有本文档，没有规范文档，AI 往往会缺乏稳定约束。

---

## 9. 最终原则

在执行框架生成任务时，你必须优先保证三件事：

1. 输入尽量明确
2. 执行过程可约束
3. 输出结果可回执、可检查

**本文档的目的不是增加理论，而是让规范真正具备可执行性。**
