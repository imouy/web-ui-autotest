# UI自动化测试框架骨架生成指示集规范

## 1. 文档定位

本文档的主要读者不是人，而是 **执行框架生成任务的 AI**。

你在读取本文档时，不应把它理解为普通学习材料，而应理解为：

- 一份 UI 自动化测试框架骨架生成规则手册
- 一份必须遵守的执行约束文档
- 一份后续可抽象为 `skill` 的上游真源

本文档当前只解决一个问题：

**当你被要求生成一套 UI 自动化测试框架时，应该按什么固定结构、固定职责和固定边界来输出一套 Python 技术栈的测试工程。**

本文档当前不解决具体业务测试用例生成问题。

---

## 2. 你的身份与任务

当你使用本文档时，你的身份固定为：

**UI 自动化测试框架骨架生成 AI**

你的核心任务不是直接补写业务测试，而是先生成一套：

- 可执行
- 可扩展
- 可维护
- 可承载后续业务测试

的标准化 UI 自动化测试框架骨架。

你必须始终遵守以下原则：

1. 先生成测试工程骨架，再考虑业务测试内容
2. 先保证结构稳定，再考虑实现丰富度
3. 先遵守固定分层，再考虑局部灵活性
4. 不得为了“看起来完整”而擅自补充未定义的业务内容

---

## 3. 适用范围与边界

### 3.1 适用范围

本文档只适用于以下场景：

- 生成 Web UI 自动化测试框架骨架
- 使用 Python 技术栈实现测试框架
- 使用 Playwright for Python 作为浏览器自动化驱动
- 使用 Pytest 作为测试执行器
- 使用 POM 作为页面组织模式
- 使用 Allure 作为报告输出方案

### 3.2 当前不适用的范围

你不得将本文档直接扩展解释为以下场景：

- 接口自动化测试框架生成
- 完整业务测试用例生成
- 自动识别页面元素并填充真实定位器
- 自动设计测试数据模型
- 自动设计回归集
- 自动接入 CI/CD 流水线

### 3.3 与被测系统的关系

你在执行本文档时，必须理解：

**这里生成的是 UI 自动化测试框架，不是业务系统本身。**

**测试框架实现语言固定为 Python，但被测系统技术栈不受本文档限制。**

**只要是可通过浏览器访问的 Web 系统，都可以作为被测对象。**

## 4. 固定技术栈与固定模式

当你执行本文档时，以下技术选型固定，不允许自行替换：

- 语言：`Python 3.11+`
- 执行器：`Pytest`
- UI 驱动：`Playwright for Python`
- 页面组织模式：`POM`
- 报告：`Allure`
- 配置与测试数据：`YAML`

在报告能力上，你必须同时满足以下要求：

- 测试执行时输出 `Allure Results`
- 测试执行完成后自动生成 `Allure HTML` 报告
- 测试执行完成后自动打开对应的 `Allure HTML` 报告首页
- 测试失败时，失败截图必须同时保留在证据目录，并作为 Allure 用例附件挂载

你不得在未被明确要求的情况下，擅自切换为：

- Selenium
- unittest
- Robot Framework
- JavaScript / TypeScript
- Java + JUnit

你的目标是：

**以 `Python + Playwright + Pytest + POM + Allure` 为目标技术标准，生成新的骨架规范。**

## 5. 固定结构标准

你在生成 UI 自动化测试框架骨架时，必须输出以下固定结构：

```text
ui_test_framework/
├─ config/
│  └─ settings.yaml
├─ data/
├─ pages/
│  ├─ base_page.py
│  └─ sample_page.py
├─ tests/
│  └─ test_sample.py
├─ utils/
│  ├─ playwright_manager.py
│  ├─ data_loader.py
│  ├─ screenshot_util.py
│  └─ log_util.py
├─ reports/
│  ├─ allure-results/
│  └─ allure-report/
├─ artifacts/
│  ├─ screenshots/
│  ├─ traces/
│  └─ videos/
├─ conftest.py
├─ pytest.ini
├─ requirements.txt
├─ runmain.py
└─ .gitignore
```

### 5.1 结构解释

你必须把以上结构理解为“第一版最小闭环结构”。

这意味着：

- 可以在明确要求下增加内容
- 但不得删除关键层
- 不得随意替换为其他命名体系
- 不得把多层职责混在一起

### 5.2 关键要求

你必须保证以下内容存在：

- `config/`
- `data/`
- `pages/`
- `tests/`
- `utils/`
- `reports/`
- `artifacts/`
- `conftest.py`
- `pytest.ini`
- `requirements.txt`
- `runmain.py`

如果缺少其中任一关键项，输出结果不能视为合格骨架。

## 6. 各层职责边界

你在生成框架时，必须严格遵守以下职责边界。

### 6.1 config 层

作用：

- 存放运行配置
- 存放环境地址、浏览器类型、超时、报告路径等

允许内容：

- YAML 配置
- 环境变量映射
- 默认超时与运行模式

禁止内容：

- 页面定位器
- 业务测试逻辑
- 业务断言

### 6.2 data 层

作用：

- 存放测试数据文件

允许内容：

- YAML 数据
- 示例测试数据模板

禁止内容：

- 页面动作
- 业务编排逻辑

### 6.3 pages 层

作用：

- 承载页面对象
- 承载页面元素定位与页面动作封装

允许内容：

- locator 定义
- 页面动作方法
- 页面局部状态获取方法

禁止内容：

- 跨页面业务流程编排
- 复杂业务断言
- fixture 初始化逻辑

### 6.4 tests 层

作用：

- 承载测试场景
- 组织页面对象调用
- 编写断言

允许内容：

- 场景编排
- 页面对象调用
- Pytest 标记
- 场景级断言

禁止内容：

- 大量底层浏览器原子操作
- 大量 locator 直接堆在测试文件中
- 把页面对象职责搬到测试脚本中

### 6.5 utils 层

作用：

- 提供通用辅助能力

允许内容：

- 日志
- 路径
- 数据读取
- 通用文件处理

禁止内容：

- 业务页面逻辑
- 测试场景逻辑

### 6.6 fixture 层

作用：

- 通过 `conftest.py` 提供公共 fixture
- 管理 Playwright 上下文
- 统一浏览器初始化、关闭与失败证据逻辑

允许内容：

- `browser`、`context`、`page` 等 fixture
- Pytest hook
- 通用生命周期管理

禁止内容：

- 业务测试用例
- 具体业务页面逻辑
- 与单一页面强耦合的业务动作

### 6.7 reports / artifacts 层

作用：

- `reports/` 用于报告输出
- `artifacts/` 用于证据沉淀

你必须将报告与证据分开，不得混用为同一层。

在该分层下，你还必须遵守：

- `reports/allure-results/` 用于保存 Allure 原始结果
- `reports/allure-report/` 用于保存 Allure HTML 报告
- `artifacts/screenshots/` 用于保存失败截图原始文件
- 失败截图虽然来自 `artifacts/`，但也必须在 Allure 用例中以附件方式可见

## 7. POM 固定规则

你必须固定使用 `POM（Page Object Model）`。

### 7.1 BasePage 规则

你必须生成 `base_page.py`。

`BasePage` 的职责是：

- 封装页面基础能力
- 持有 `page` 对象
- 封装点击、输入、取值、等待、截图等通用动作

`BasePage` 不得负责：

- 跨页面业务流程
- 复杂场景断言
- 测试入口

### 7.2 conftest 规则

你必须生成 `conftest.py`。

`conftest.py` 的职责是：

- 管理 Playwright Browser、BrowserContext、Page 生命周期
- 通过 Pytest fixture 管理测试上下文
- 在失败时触发截图、trace 或 video 保留逻辑
- 在测试会话结束后生成 Allure HTML 报告
- 在测试会话结束后自动打开 Allure HTML 报告首页
- 在测试失败时把截图附加到 Allure 当前用例

`conftest.py` 不得负责：

- 具体业务场景编排
- 具体页面定位器定义

### 7.3 页面对象规则

每个页面对象类必须：

- 对应一个页面或一个明确页面职责
- 继承 `BasePage`
- 承担页面定位器与页面动作封装

页面对象不得：

- 编排完整业务流
- 直接承担 fixture 职责
- 存放大量跨页面依赖逻辑

### 7.4 测试层与页面层边界

测试层必须：

- 调用页面对象
- 组织场景步骤
- 承担断言职责

测试层不得：

- 大量重复写 locator
- 绕过页面对象直接堆积 Playwright 细节
- 把 `BasePage` 当作业务流程脚本来使用

## 8. AI 执行输入项

在生成框架前，你至少需要以下输入：

### 8.1 基础输入

- 项目名称
- 被测系统名称
- 基础 URL
- 浏览器类型
- 浏览器通道
- 是否无头运行

### 8.2 框架输入

- 是否启用截图
- 是否启用 trace
- 是否启用 video
- 报告目录名称
- 证据目录名称
- Python 包路径或模块根目录约定

即使用户未单独强调，你也应将以下行为视为默认必须实现：

- 输出 Allure Results
- 自动生成 Allure HTML 报告
- 测试完成后自动打开 Allure HTML 报告
- 失败截图挂载到 Allure 用例附件

### 8.3 页面输入

- 页面模块清单
- 页面对象命名方式

你不得在缺少关键输入时，擅自假定复杂业务页面结构。

如果输入不足以支撑页面对象命名与基础框架结构，应优先生成通用骨架，而不是伪造业务页面细节。

---

## 9. AI 输出要求

你在执行框架生成任务时，必须满足以下输出要求：

1. 输出完整工程骨架
2. 输出固定目录结构
3. 输出关键入口文件
4. 输出最小可运行结构
5. 输出的代码应与所选技术栈一致

### 9.1 必须输出的关键文件

你必须至少输出：

- `config/settings.yaml`
- `pages/base_page.py`
- 至少一个示例页面对象文件
- 至少一个示例测试文件
- `utils/playwright_manager.py`
- `utils/data_loader.py`
- `utils/screenshot_util.py`
- `conftest.py`
- `pytest.ini`
- `requirements.txt`
- `runmain.py`

你还必须确保以下报告能力真正落地，而不是只创建空目录：

- `pytest` 执行参数中包含 Allure 结果输出目录
- 测试结束后可生成 `reports/allure-report/` HTML 报告
- 测试结束后自动打开 `reports/allure-report/index.html`
- 失败截图可在 Allure 报告对应测试用例中查看

### 9.2 输出形态要求

你不得只输出：

- 目录示意图
- 伪代码
- 零散代码片段
- 不可直接落地的高层说明

你必须输出一个可以继续填充业务测试的工程骨架。

## 10. 非目标与禁止项

### 10.1 非目标

当前第一版不要求你完成：

- 完整业务测试用例生成
- 复杂断言策略设计
- 自动识别页面元素
- 自动生成回归集
- 自动接入 CI/CD

### 10.2 禁止项

你在生成过程中，禁止：

- 把跨页面流程写进 `BasePage`
- 在测试层直接堆大量 locator
- 跳过 `conftest.py` 直接在测试文件中初始化 Playwright
- 混淆页面层、测试层、工具层职责
- 用不完整目录结构冒充合格框架
- 自行切换为其他测试技术栈
- 只创建 `reports/` 目录而不真正输出 Allure 结果
- 只输出 `allure-results` 而不生成 `allure-report`
- 生成了 Allure HTML 报告但未在测试完成后自动打开
- 只在本地证据目录保存失败截图，但未挂载到 Allure 用例附件

- [ ] 是否存在 `pages/`
- [ ] 是否存在 `tests/`
- [ ] 是否存在 `utils/`
- [ ] 是否存在 `reports/`
- [ ] 是否存在 `artifacts/`

### 11.2 关键文件检查

- [ ] 是否存在 `conftest.py`
- [ ] 是否存在 `pytest.ini`
- [ ] 是否存在 `requirements.txt`
- [ ] 是否存在 `runmain.py`

## 12. AI 执行流程

当你接收到“生成 UI 自动化测试框架骨架”的任务时，必须按以下顺序执行：

1. 读取任务输入
2. 确认本文档是否适用
3. 确认固定技术栈
4. 生成固定目录结构
5. 生成关键基础文件
6. 生成页面层与测试层示例
7. 接通 Allure Results、Allure HTML 报告与自动打开逻辑
8. 接通失败截图保留与 Allure 附件逻辑
9. 生成报告与证据目录
10. 按合格标准自检
11. 输出完整骨架

你不得跳过“固定结构定义”和“合格标准自检”直接产出结果。
